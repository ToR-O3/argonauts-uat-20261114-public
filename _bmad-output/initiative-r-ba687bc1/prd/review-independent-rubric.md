# 独立レビュー: rubric walker / 入力照合

## Verdict

指定コマンド・追加先・READMEだけという製品変更範囲・既存内容保持は正確に伝わり、実装に必要な重大な欠落やブロッカーとなる曖昧点はない。独立に公式rubricと受付入力を照合した結果、製品要件は着手可能だが、入力にない工程文書の保存先制限を確定事項にしているため、その部分は修正が必要である。

## 優先する修正

1. **High / R-1:** PRD 50行の工程文書保存先のallowlistを削除するか、別途承認された工程規則の出典を示す。受付の「製品変更READMEのみ」は、工程文書のPR除外や保存先制限を意味しない。
2. **Low / R-2:** PRD 48・50行の工程運用を製品受入条件から分離する。追加の検証や担当権限を依頼者が要求した製品要件として扱わない。
3. その他に修正必須の製品要件はない。レビューのために新しい要件・質問・文章量を追加しない。

## 読了した根拠と評価範囲

- `prd-light-readme-top5-text.md` 全文（58行）
- `.template.md` 全文、特に25行の Done when
- `.memlog.md` 全文（過去の自己レビューの結論は追認せず、判断履歴として参照）
- 依頼入力全文と受付の決定（本レビューへの入力）
- `README.md` 全文。「wordfreq の実行」の既存コードブロックは9–23行。
- `openspec/specs/wordfreq-cli/spec.md` 全文。FR-2（35–45行）とFR-3（51–64行）が指定オプションの既存契約を裏付ける。
- 公式 `bmad-facilitate` の `references/rubric-planning.md` と `references/guidance-planning.md`

低stakesの単一文書変更として判定した。これは要求文書の独立検査であり、READMEの実装完了・実CLI・テストの合格を検証したものではない。

## Findings

### R-1 — High: 入力にない工程文書の保存先制限

- **場所:** PRD 50行、Honest scope / Usable downstream。
- **根拠:** 入力は「変えるのは README.md だけ」。受付決定は、それが製品変更の範囲であり、工程文書をPRから除く制限ではないと明示している。指定ディレクトリ以外を禁止する決定は入力にも `.memlog.md` の判断履歴にも示されていない。
- **影響:** 製品変更自体は正しくても、後続担当が未承認の工程制約を依頼者の決定と誤認し得る。ユーザーが述べていない決定を確定事項として扱うため、公式レビュー規則に従いHighとする。
- **修正:** allowlistの文を削除し、必要なら「READMEのみは製品変更の範囲を指し、工程文書と区別する」と置換する。別途の明示的な工程規則があるなら、その出典と位置づけを示し、依頼者の製品要件と混同しない。新たな承認待ち事項は作らない。

### R-2 — Low: 工程上の引継ぎと製品要求の混在

- **場所:** PRD 48行の既存テスト・一時入力・文字記録、50行のcommit・push・kanban担当権限。Earned / Honest scope。
- **根拠:** 元入力が求めるのはREADMEへの1行追加である。`.memlog.md` 9・15行に実CLI検証への引継ぎは記録されているため、履歴との矛盾ではないが、元入力から必須の製品受入条件が増えたわけではない。
- **影響:** 後続工程への助言がFR-1とは別の製品要件として読まれる可能性がある。現状でもFR-1とSuccessは明確なため、ブロッカーではない。
- **修正:** 工程上の引継ぎであることを明記するか、工程記録側に留める。本レビューは既存テスト・実CLIの実施禁止を提案しない。今回のレビューへのcommit・push・kanban禁止はそのまま守る。

## Template Done when

- **Every FR can be checked:** 適合。FR-1は指定の1行追加として差分で検査可能。
- **Scope edges are explicit:** 製品範囲は適合。工程範囲の追加制約はR-1の修正対象。
- **A builder could start from this file alone:** 製品編集には十分。新機能設計、Architecture、画面設計、追加の利用者確認は不要。

## 結論と非実施事項

製品要求の重大な落ち・追加の未決事項は見つからず、Highの工程制約1件とLowの工程混在1件を報告する。対象PRD・template・memlog・README・既存specは変更せず、このレビューだけを作成した。CLI・テスト実行、commit、push、kanban操作は行っていない。
