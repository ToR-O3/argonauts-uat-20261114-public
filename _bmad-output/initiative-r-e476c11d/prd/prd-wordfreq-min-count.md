## 目指す状態

`--min-count N` で低頻度語を表示から外し、text/json/htmlで同じ条件を使えるようにする。既定1で従来出力を保つ。追加自体は決定済み。具体的利用者・実負担・理由・期限は未確認であり、需要・緊急性・事業効果を創作しない。

## 利用者と利用の流れ

利用者像はA-01、代替手段はA-03の仮定。実名personaや実体験を作らず、単一CLIの操作として記す。UTF-8ファイルに閾値・top・形式を指定し、有効なら結果、不正なら使い方エラーを得る。この依頼上の必要をFR-1〜FR-4が満たす。

## 用語

- **語**: Unicode単語文字列を抽出しcasefoldした集計キー。
- **出現回数**: 入力全体でその語が現れた回数。
- **閾値N**: 1以上の整数。N未満の語を表示から除く。
- **top**: 表示種類数の上限。1以上の整数、既定10。
- **順位**: 回数降順、同数なら正規化後初出順。HTMLでは表示行の1始まり連番。
- **総数**: min-count/top前の全語の回数の和。種類数・表示行の和ではない。

## 機能と要求

### FR-1 閾値指定と検証

`--min-count N` は1以上の整数、既定1。0・負数・非整数・非数値・値欠落は入力読込前にexit2。既存の使い方エラー同様stderrで通知し、stdoutは空、Traceback/エラーHTMLなし。独自の字句制約・上限は加えない。

### FR-2 共通の表示対象

全形式でN未満を除外し、NちょうどとN超を保持。**min-count除外が先、その後top**。両値に相互制約を課さず、回数降順・同数時初出順を保つ。未指定と明示1は従来出力と一致する。順序は決定済みで再質問しない。

### FR-3 空結果とHTML総数

空入力・全件除外は正常終了。textは空文字、JSONは `[]` と末尾改行1つ。HTMLは既存メタ情報、見出し3列、データ0行、既存空状態文言を保つ。総数はmin-count/top前で、抽出語0件（空ファイル・空白のみ・句読点のみ）は0。抽出語があり閾値で全件除外されても元の正の総数を保つ。basenameのみの表示も不変。

### FR-4 試験と説明

正常・境界・異常・既定・併用のpytestを追加し既存全試験を実行する。READMEで指定法・既定・順序・エラーを説明し、品質は実HTMLをブラウザ確認する。受入条件は「成功基準と受入」に記す。

## 共通規則

- **RULE-1**: Unicode抽出/casefold・正規化後初出順は不変。閾値は表示条件であり入力・元の集計を変更しない。
- **RULE-2**: 元総数確保→閾値除外→top制限→形式化の意味を共有する。形式別の条件にしない。
- **RULE-3**: 未指定=1、既定text/top10。変更のない実行の出力・並び・構造を保つ。

## 成功基準と受入

**SM-1**: 現ソースにはmin-count未実装。目標はAC1〜AC5の全条件成立。事業成果の数値基準は設定しない。

**SM-2**: SM-1のcounter-metricは既定出力の差異、既存試験失敗、見た目/範囲逸脱。目標は新規の後退なし。AC6・AC7・実HTMLで判断する。本工程でpytest結果は測定していない。

- **AC1**: 全形式でN未満除外、Nちょうど/超保持。空入力・全件除外もFR-3の形式と正常終了を維持。追加pytest/実CLIで確認する。
- **AC2**: 全形式の未指定/明示1/従来stdoutが一致。既定text/top10、並び・構造を維持。同数と10種類超を含め同じ入力・引数で変更前後比較する。
- **AC3**: `0` / `-1` / `1.5` / `abc` / 値欠落はexit2、stderr通知、stdout空、Traceback/エラーHTMLなし。入力パス不存在でも引数エラーを先に確認する。
- **AC4**: min-count除外後にtop。top < min-count / top > min-count、同数順、両オプションの指定順を実CLIで確認。回数降順では出力だけで処理順を区別できない場合があるため、選択処理も確認する。
- **AC5**: HTML総数は片方/両方の絞込み前。空入力0、抽出語がある入力を閾値で全件除外した場合でも元総数を確認する。
- **AC6**: 正常・境界・異常・既定・併用の追加pytestと既存全試験を実行。実コマンド/環境/収集件数/終了値/結果と全形式のCLI原本を残す。0件収集・未実施を成功にしない。
- **AC7**: CI追加変更/依存追加なし、他契約不変。対象差分・依存定義・既存回帰で確認。必要な既存CI結果をローカル成功で代用しない。

後続試験用の明示期待値（新機能の実行結果ではない）: `Zoo apple APPLE zoo banana` は総数5。N=2/top10はzoo2,apple2、N=2/top1はzoo2、N=3は全除外/HTML総数5。N未満/ちょうど/超の混在入力も試す。

- **RULE-4**: 品質が対象headの実CLI生成HTMLをブラウザで確認する。既定の見た目不変、絞込み時の行・総数・全除外を通常1280×900/狭幅320×900 CSS px・DPR1で確認し、head/差分、実argv、入力/HTML原本、画像、閲覧結果を残す。DOM/CSS一致やcapture成功だけでは合格にしない。不足は未検証。
- **RULE-5**: 標準ライブラリのみ、HTMLのUTF-8・escape・静的性、入力不変・プライバシー境界を保つ。依存/CI追加で通さない。

`docs/wordfreq-html-verification.md` は証拠形式の参考。前依頼の固定head/scope/AC番号/合格は流用せず今回へ対応付け、環境不足は報告する。PRDビューは製品証拠にしない。

独立レビューを反映した検証の具体化:

- AC2の比較元は実装着手前の依頼branchのheadを記録し、同じ入力原本・argv・環境で変更前stdoutを保存する。変更後同士の比較だけで従来互換を証明しない。
- RULE-4の既定表示比較は比較元headのHTMLと画像も保存し、入力・basename・ブラウザ版・フォント・viewport・DPRを揃える。環境差は記録する。
- AC4は出力比較に加え、品質が閾値除外→top制限の該当ファイル・行またはdiffを記録する。出力一致だけを内部順序の証拠としない。
- AC1/AC6には空白のみ・句読点のみ（抽出0語、総数0）と、`Straße STRASSE`をN=2でstrasse 2として残すUnicode casefoldの閾値試験を全形式で含める。
- AC3の異常値群を各形式と交差させ、入力不存在でもexit2・stderr通知・stdout空を確認する。有効なN>1では各形式の既存入力失敗（不存在・ディレクトリ・開けない・不正UTF-8）がexit1のままであることも確かめる。権限試験の実行不能は未検証と区別する。
- AC7の既存CIは品質がそのheadに対する必須contextとActions/statusの結果をチーム手順で有限回確認する。CIを待つ処理・CI追加変更は導入しない。未報告・pending・不調をsuccessに置き換えず、存在しないCIを新しく要求しない。
- READMEは入力に語があっても閾値で全除外され得ること、その場合は閾値を下げることを説明する。既存HTML空状態文言は変更しない。

引数字句の追加仕様は設けず、既存`--top`と同じargparse/intの環境上の変換規則に従う。実装独自の上限や変換制限解除は追加しない。重複指定は既存argparseの単一値オプションと同じく有効値の最後を採用し、途中の整数変換エラーはexit2になる。これらは新たな製品判断でなく既存の引数解析方式の継承である。

## 変更境界

現物をread_fileで確認した根拠:

- `wordfreq/__main__.py`: filename/top/format、top前total、形式別出力。min-count追加が必要。
- `wordfreq/aggregator.py`: 安定ソートと入力非変更。`top_words(counts, n)` の既存利用を壊さない。
- `wordfreq/formatters.py`: 純粋整形。textのcount/TAB/word/改行、JSONのword/count配列・改行、HTMLの既存構造・CSS・escapeを維持。
- `wordfreq/sources.py` / `tokenizer.py`: UTF-8実ファイル/入力境界/Unicode抽出/casefoldは不変。
- `README.md`、`tests/test_cli.py` / `test_aggregator.py` / `test_formatters.py`: 既定・初出順・空・総数・安全性の契約を確認。既存試験は残す。
- `pyproject.toml`: 実行時dependencies空、開発用pytestのみ。変更しない。

読込/decode失敗exit1、引数エラーexit2、ファイル名復号、basename限定、formatterの呼出契約と純粋性を保つ。
