## 要約

README.mdの先頭説明文を分かりやすくするための検討資料である。依頼者は新しい文をまだ選んでいない。現物の見出しは1行目の `# argonauts-uat public`、対象は3行目の `Argonauts v1.10 acceptance test repository.` であり、見出しは変更しない。

提案は「Argonauts の動作を確認するための公開受入テスト用リポジトリです。」の1行への置換である。文案、v1.10の省略、検証基準はPM仕様承認待ち。このBriefと後続PRDは工程文書であり、READMEの実装や受入完了を意味しない。想定読者と実施時機の理由は未確認のため、無人実行の結果はpartialとする。

## 課題

依頼は「README.md の先頭の1行の説明文を、もっと分かりやすい文に書き換える。新しい文をどうするかは、まだ決めていない。変えるのは README.md だけ。」である。根拠はREADME.md全37行とこの依頼であり、具体的な読者の困りごと、理解に要する時間、事業上の損失は測定されていない。wordfreqの説明は現物の別節にあるが、今回の課題に含めない。

## 解決案

3行目だけを次の文にすることを提案する。

> Argonauts の動作を確認するための公開受入テスト用リポジトリです。

public／Argonauts／acceptance test repositoryという現在の対象・目的を明確化する。新機能の説明は加えない。現行のv1.10を最新版へ勝手に置換しない。候補はバージョンを省いているため、省略の是非を文案の選択と分けて承認する必要がある。

## 選択肢との違い

現状維持は差分を生まないが、説明を改善する依頼には応えない。候補文は日本語で用途まで一文にまとめ、変更を1行に限定する。v1.10を残す別案は未選定であり、依頼者が省略を認めない場合はPMが再提案する。市場優位性や新規性を主張する変更ではない。

## 対象読者

リポジトリを初めて読む日本語読者が、冒頭だけで何のための公開リポジトリか判断できることを想定する。これは未確認の読者仮説であり、依頼者から具体的人物や優先読者の指定はない。後続の利用者は仕様を承認するPM、計画・実装担当、独立品質担当である。

## 成功基準

次はすべて検証基準案であり、実行済み・承認済みではない。

- 変更後の3行目がPM承認後の具体文と完全一致する。候補のまま承認されれば解決案の引用文を使う。
- 当該1行だけから、Argonauts／公開／受入テスト／リポジトリ／動作確認の意味を判別できる。
- 1–2行目と4行目以降は開始HEAD `69b97f1c9dfa7211367a9bdd0af885d80d8bf380` のREADME.mdとバイト単位で一致する。改行・末尾改行も保持する。
- git全差分で他製品ファイルの不変を確認する。工程文書の除外は指定5領域だけとし、具体名が確定するまで除外を広げない。未追跡ファイルも確認する。

完全一致、不変性、意味のいずれかを満たさなければ合格にしない。理解度の改善率など、根拠のない数値目標は設定しない。

## 範囲

固定判断はflow full。将来の製品変更はREADME.mdの3行目だけであり、見出し・空行・他の全行を保持する。工程文書は許可されるが、本カードではREADMEを絶対に編集せず、テストコードも作らない。後続の検証テストは計画・実装担当が許可済み工程文書領域内に置き、製品ファイルを追加しない。

工程文書の配置境界は `.planning/`、`openspec/`、`_bmad-output/`、`.compound-engineering/`、`docs/solutions/` とカードで指定済み。本依頼の成果物を個別に識別し、領域全体を検査対象から外さない。独立レビューで補足した承認・意味判別・差分検証の詳細はPRD「独立レビューによる補足」を参照する。

機能・構造を変更しないためArchitectureは不要。wordfreq、他の製品ファイル、無関係な既存要求・成果物を変更しない。親担当が工程文書のcommit・依頼branchへのpush・カード添付を行う。
