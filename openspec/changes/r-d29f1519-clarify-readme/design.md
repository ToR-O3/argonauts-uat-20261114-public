# Design

## Context

動機と全受入条件はproposal.mdを参照。本書は元版 `71b7a0a19992d03e63d2b71fbb85661c59aba159` に対するrevise=1。PM判断 `t_c5dd0fce` run91と差戻し `t_296a5f28` run92により文案・v1.10保持・検証基準は確定した。旧版の省略案を採用せず、過去の記録は履歴に保持する。これは依頼者選択ではなくPM決定であり、本改訂の再承認後のみ計画へ進む。機能・構造変更がないためBMAD Architectureは不要。

## Goals / Non-Goals

**Goals:** 承認後に対象1行だけを置換し、完全一致・意味理解・非対象バイト保持・範囲を直接検証する。

**Non-Goals:** 本工程でのREADME編集、全文再出力、改行正規化、バージョン更新・省略、新機能・新依存。未確認の読者像・実施理由・改善率を事実として扱わず、追加調査を必須にしない。

## Decisions

1. バイト単位の行境界を保持し3行目のみ `Argonauts v1.10 の動作を確認するための公開受入テスト用リポジトリです。` に置換する。原本は `69b97f1c9dfa7211367a9bdd0af885d80d8bf380:README.md`。1–2行目と4行目以降は改行・末尾改行まで保持する。全文の文字列再出力や改行正規化はこの条件を壊し得るため採用しない。
2. 再承認後に `.planning/argonauts/r-d29f1519/` 配下で検証入力・検証ファイルを用意する。製品範囲を増やすルートtests等への追加は行わない。固定原本と確定期待文字列を使い、旧文では一致検査が失敗し、置換後に同じ検査が成功することを計画・実装担当が確認する。
3. 品質は当該1行単独からArgonauts v1.10・公開・受入テスト・リポジトリ・動作確認用途を読み取り、他節参照や専門語の補足なしで平易に言い換えて文字で記録する。語の存在・完全一致のみで明確化の合格を代用しない。
4. 全git差分（追加・削除・rename、staged/unstaged/untracked含む）でREADME以外の製品変更0、無関係な工程文書変更0を確認する。工程文書5領域は本依頼の成果物を明示リストで識別し、領域全体を無条件除外しない。
5. 品質は実行コマンド・終了値・比較原本・対象head・判定をVERIFICATION.md等の文字の証拠に残し、PMがread_fileで読めるようにする。画像・圧縮ファイル閲覧をPMに求めない。

## Risks / Trade-offs

- [旧候補の混入] → 本改訂の再承認記録に最終文・v1.10保持・検証基準・承認者・対象文書版を一組で残す。旧版の承認は流用しない。
- [原本以後の対象外変更] → 実装開始前に照合し、発見時は自動復元せず比較原本の更新をPMへ確認する。
- [一致だけで明確化と誤認] → 独立品質の単独行の言い換え判断を併用する。理解度向上の実測は主張しない。

## Migration Plan

データ移行・配備変更なし。再承認→計画→検証のRED→3行目のみ編集→GREEN→独立品質の順。問題があれば当該行の変更だけを取り消し、他行・他ファイルを復元し直さない。取消直前に3行目が今回適用した値と一致することを確認し、別の変更があれば上書きせず停止してPMへ確認する。カード単位のcommit/pushは依頼branchだけに行う。内容選択の未決事項なし。着手時の承認版照合、未コミット検査対象の特定、許可成果物一覧と意味判定の記録、最終headの再照合はtasksの共通ガードに従う。
