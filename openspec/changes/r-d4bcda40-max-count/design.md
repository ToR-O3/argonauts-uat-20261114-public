# Design

## Context

動機はproposal.mdのWhy、外部契約はspecs/wordfreq-cli/spec.mdを参照。現行`wordfreq/__main__.py`はargparseで整数のmin-countを受け、入力取得・正規化集計・元総数計算・下限選択・top・各formatterの順に合成する。`top_words`は回数降順の安定ソートで同数初出順を守る。

新Architecture文書は不要だが、整数の扱いと選択順序の技術判断を実装前に残すため、この小さなdesignを作る。

## Goals / Non-Goals

**Goals:**
- 共通選択の一箇所で任意の上限を加え、全形式の契約を保つ。
- 元総数・元Counterを保持し、仕様の各条件を実CLIと内部経路の試験で直接区別できる構成にする。

**Non-Goals:**
- filterのために部品APIや入力境界を再設計しない。空結果のために入力取得を短絡しない。
- HTMLのCSS・空状態文言や既存検証サービスを変更しない。CI・依存・専用サービスを追加しない。

## Decisions

1. **省略はNone、明示値はargparseのtype=int。** 任意の大きい整数を上限なしの代用品にしない。0/負数の正値検証は加えない。既存min-countは正値だが、その制約をmaxへコピーすると依頼の整数・値以下という条件を狭める。min>maxをエラーにする代案も両条件の共通部分という契約に不要なので不採用。
2. **同一の共通選択へAND条件を追加。** 元Counterの項目順を維持し、`count >= min_count`かつ`max_count is None or count <= max_count`で新しい選択Counterを作り、既存top_wordsへ渡す。formatter別の選択は分岐の不一致を招くので不採用。topしてから除外する代案は表示可能な低頻度語を失うので不採用。
3. **元総数は全フィルタ前に計算。** 現行の集計・総数経路を保ち、htmlへ元総数と共通pairsを渡す。選択後の合計を渡さない。正常空結果の出力は既存formatterに任せる。
4. **TDDで実CLI契約と内部順序を分けて確認。** tests/test_cli.pyの既存bytes/HTMLParser補助を再利用できる。包含・上下限AND・max1・Unicode・tie・top前選択は明示期待値を使い、省略互換は既存保存原本または変更前に固定したバイト列と比較する。新実装から期待値を作らない。top呼出しのspyで閾値が先と元Counter不変を直接確認する。
5. **入力エラーと引数エラーを区別。** 非整数/欠落、既存min/topの不正値は読込みspyで未取得と確認する。有効なmax0/負数/逆転では空集合が予測できても入力を読むので、既存の入力失敗exit1を維持する。
6. **README例は1つ。** 入力と期待JSONを併記し、同じコマンドをpytestで実行する。上限の説明、全件除外の調整、総数がmax前でもある説明だけを整える。

## Risks / Trade-offs

- [min-countの正値検証をコピーする] → 0・負数・`--max-count=-1`の受理と空結果試験。
- [ANDでなくOR、境界不包含、top後除外] → 2/3/1回の混在、min=max、三条件それぞれが除外するケース、内部spy。
- [互換比較が変更後同士になる] → 既存原本または変更前の固定期待バイト列・exit・stderrを保存して比較。
- [HTML元総数や見た目の回帰] → 元集計を保持し、品質が対象headで実CLIを再生成して既存の通常幅/狭幅の独立確認を行う。PM向けには条件ごとの結果・画像閲覧内容を文字で記録する。
- [小機能の試験が冗長になる] → 既存補助を再利用し、仕様の異なる失敗方向を直接示すケースだけを追加する。

## Migration Plan

データ移行・依存導入・版更新は不要。任意引数の追加なので既存呼出しはそのまま利用する。問題があれば本変更を通常のrevertで戻す（本工程では実装・deployしない）。
