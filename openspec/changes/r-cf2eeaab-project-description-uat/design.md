# Design

## Context

動機と範囲はproposal.md参照。起点 `c572613dc626160db2eb3bf4a41c95fc8283b828` のpyproject.tomlにはdescriptionがない。新規追加は依頼者判断で解決済み。この文書はarchitecture変更の提案ではなく、製品ファイルを増やさず不変条件を直接検証する方法を確定する。

## Goals / Non-Goals

**Goals:** 単一キー追加を、値・構文・既存データ・実際の差分の観点から確認できるようにする。

**Non-Goals:** TOML全体の再シリアライズ、既存試験の書換え、検証用依存の追加、CI変更。別のArchitecture文書は不要。

## Decisions

- `[project]` 内へ `description = "argonauts-uat public (UAT)"` の1行だけを挿入する。TOMLライブラリによる全文書換えは、並びや空白の不要変更を避けるため採用しない。
- 検証がスクリプトを必要とする場合、後続PLANで `.planning/argonauts/r-cf2eeaab/` 内に標準ライブラリのみの検証ファイルを作る。製品テストには追加しない。実装前は値の欠落を失敗として観測し、実装後は同じ検査で成功を確認する。
- Pythonのtomllib等による正常解析と値の厳密比較に加え、完成後の解析結果からdescriptionだけを除いたものを起点の解析結果と比較する。対象行だけを除いたバイト列も起点と比較し、項目不変だけで見逃す整形変更を検出する。
- Gitの全差分で、工程文書の明示された置き場所（.planning、openspec、_bmad-output、.compound-engineering、docs/solutions）以外の変更がpyproject.tomlだけであることを確認する。差分と検査の起点SHAを証拠に明記する。
- 品質は検証head、実行コマンド、終了コード、実結果、条件別判定を文字の検証記録に残す。PMに画像や圧縮ファイルの読解を求めない。

## Risks / Trade-offs

- [完成値への二重追記] → 文字列の厳密一致で失敗とする。
- [同名キーの別テーブル追加・重複] → TOML解析とproject配下の値の検査を併用する。
- [他項目・製品ファイルの便乗変更] → 起点との差分・解析結果・対象行除外後バイト列を確認する。
- [危険パス] → smartでも自動マージせず、人のマージに渡す。

## Migration Plan

データ移行や実行環境変更はない。後続で1行を追加し検証、独立品質確認を経て人がマージする。取り消す場合も当該追加行のみを戻し、依頼範囲以外へ影響させない。
