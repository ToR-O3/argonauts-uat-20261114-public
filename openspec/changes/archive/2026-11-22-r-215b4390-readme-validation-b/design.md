# Design

## Context

動機と変更境界は proposal.md、文書の状態は specs/readme-validation-b/spec.md に従う。構成変更はないが、依頼主が後続入力にdesignを含めると回答したため、最小の実施判断を記録する。

## Goals / Non-Goals

**Goals:** 既存本文・書式を保持した末尾追記とし、差分で1行だけの変更と確認できるようにする。

**Non-Goals:** 自動追記機能や新しい試験の実装、文書全体の整形、検証合格の認定は行わない。

## Decisions

- README.mdに指定文字列を直接追記する。テンプレート生成やスクリプト追加は、1行の変更に不要なため採用しない。
- 余分な空行や引用符は追加せず、既存の改行形式を保持する。全文の再整形は既存内容を変える危険があるため行わない。
- 差分・最終行・出現回数・変更ファイル一覧を既存のCLIで確認し、結果を工程の検証記録に残す。コード・試験を変更しない制約に従い、試験ファイルを新設しない。
- 人の回答に従いskip_specsを使わず、指定行の存在だけのspecを作る。これにより製品の振る舞いの要件は増やさない。

## Risks / Trade-offs

- [指定文字列の誤記や重複] → 最終行の完全一致とREADME全体での1回のみの出現を確認する。
- [既存内容の誤削除や余分な変更] → 変更前後の差分と製品の変更ファイル一覧を確認する。

## Migration Plan

データ移行や新しい配備手順は不要。通常の文書変更として取り込み、戻す場合は今回追記した1行のみを取り除く。
