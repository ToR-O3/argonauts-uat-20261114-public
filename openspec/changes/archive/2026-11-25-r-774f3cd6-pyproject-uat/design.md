# Design

## Context

proposal.mdとspecs/package-metadata/spec.mdの新設契約に従う。OQ-1は受付t_78c8849eの2026-11-24T13:00:38.567271+00:00の回答で解消した。指定連結元 `argonauts-uat public` は現物の旧値ではない。Brief・PRDも同じ判断へ改訂する。Architecture変更は不要。本工程は文書改訂のみで、PMの改訂仕様承認・計画・実装を代行しない。

## Goals / Non-Goals

**Goals:** description新設と完成値 `argonauts-uat public (UAT)`、無関係な差分の排除を直接確認できるようにする。

**Non-Goals:** 連結元の推測、他の説明文への置換、依存・製品試験ファイル・CIの追加変更、TOML全体の整形。

## Decisions

- 依頼者判断「②を選ぶ。description を新設してよい。連結元の文字列は「argonauts-uat public」、完成値は「argonauts-uat public (UAT)」とする。」を採用する。新設未承認という旧停止条件は回答済みとして置換する。
- 不変比較の実装前基準は `b34cba0d008923e7f5267ce52d5403492ea53925` のpyproject.toml（description欠落）。指定連結元とこの基準の役割を分ける。実装直前に対象と基準を再照合し、不一致なら編集せずPMへ返す。
- 改訂仕様承認後はdescriptionの必要な1行のみを新設する。全体再シリアライズは使わない。
- Python標準tomllibで前後を解析し、変更後のdescriptionの固定完成値との完全一致、および変更後からdescriptionを除いた構造と変更前との一致を検証する。変更前に存在しないキーを参照して連結しない。
- 生テキストのgit差分と未追跡ファイル一覧も確認し、他項目・書式・依存・他製品ファイルの不変を検証する。スクリプトは工程管理領域に置き、具体的コマンドは計画で確定する。
- 品質はhead・製品commit・ファイルSHA-256・基準commit・コマンド・終了コード・条件別結果を文字の検証文書へ記録し、PMに画像や圧縮ファイルを開かせない。

## Verification contract for planning

- 改訂仕様のPM承認対象は文書commitまたはSHA-256で特定する。旧仕様の承認と依頼者の新設許可を組み合わせて実装許可としない。
- 比較元treeを上記基準commit、比較先を製品commitとして固定する。追跡済み変更（追加・削除・改名・modeを含む）、index、作業ツリー、未追跡一覧を確認する。工程成果物の除外パスと用途も全件記録し、単に工程ディレクトリ内という理由で任意コードを除外しない。
- 追加したdescriptionの1行を除いた編集後バイト列と編集前バイト列の一致で、既存部分の空白・改行・末尾改行を含む書式不変を確認する。
- 検証スクリプトは正しい値の成功と、工程管理領域の負例（欠落、接尾辞重複、異なる値、他項目変更、不正TOML）の拒否を確認する。製品へ負例を書き込まない。要件不一致と実行エラーを区別し、編集前の期待失敗は解析・基準取得が成功し完成値条件だけ不一致の場合に限る。
- 製品commitのblobから算出したSHA-256と検証ファイルのSHA-256の一致を品質も確認する。必須条件の失敗・実行不能は未完了として停止し、残存差分と理由を記録してPMへ返す。無関係な変更による修復や他者差分の一括復元をしない。

## Risks / Trade-offs

- [指定入力を現物の旧値と混同] → 証拠にdescription欠落と指定連結元を別々に記録する。
- [接尾辞の重複] → 固定完成値との完全一致で失敗として観測する。
- [構造比較が書式変更を見逃す] → 生テキスト差分を併用する。
- [工程成果物を製品差分と混同] → `.planning/`、`openspec/`、`_bmad-output/` を分けて一覧化する。
- [危険なパスの編集] → 受付lightよりfullを優先した理由を最終報告まで引き継ぐ。
