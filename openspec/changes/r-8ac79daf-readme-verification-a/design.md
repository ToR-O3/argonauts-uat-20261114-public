# Design

## Context

動機と範囲は[proposal](proposal.md)、受入契約は[spec](specs/readme-verification-note/spec.md)を参照。コードや依存には触れないため独立したBMAD Architectureは不要。本書では末尾改行と検証方法の扱いだけを明確にする。

## Goals / Non-Goals

**Goals:** 既存バイト列を保持した最小追記と、その差分による確認。

**Non-Goals:** 新規のテストファイル・検証基盤、実行時機能、句点追加、通し検証実績の認定。

## Decisions

- 追記前にREADMEの末尾と改行を確認する。既存末尾が改行済みならその直後に指定行と末尾改行を追記する。未改行なら既存内容を保持したまま行区切りを補い、指定行を独立させる。文書全体の再生成や改行形式の一括変換は、既存内容を変えるおそれがあるため採用しない。
- テストとコードの変更禁止を優先し、検証は既存ツールによる末尾・差分・変更パスの確認で行う。新しい試験コードは追加しない。工程の検証記録は別文書に残す。
- READMEの最終行の内容を完全一致で判定する。通常の末尾改行は許容するが、指定行の後の空行や句点追加は不合格とする。

## Risks / Trade-offs

- [末尾以外の整形が混ざる] → 変更前後の全差分で既存行の削除・書換えがないことを確認する。
- [文字列の取り違え] → 全角括弧、ASCIIコロン、空白、日付を含む指定行と完全一致で比較する。
- [工程文書と製品変更の混同] → ファイル差分を分類し、製品変更はREADMEの1行だけと確認する。

## Migration Plan

データ移行・依存更新なし。後続実装工程で追記し、品質工程で差分確認する。取り消す場合は当該追記だけを戻し、既存READMEを保つ。
