## 2. 安全な静的HTMLとメタ情報（AC1・AC2・AC5）
- [ ] 2.1 単語・basenameを安全な表示テキストとして埋め込むHTML整形を作り、順位・単語・回数の見出し、UTF-8宣言、内包CSSだけの1枚文書を返す。整形単体試験で空pairs、特殊文字 `& < > " '`、タグ・イベント候補が表示文字となり、余分なタグ・スクリプト・外部リソースが生成されないことを確認し、部品契約を文書化する。
- [ ] 2.2 CLIへhtml形式を接続し、top前countsからの総数と実行環境のbasenameを整形へ渡す。入力パスはtitle/属性等にも出さない。実CLI試験で `zoo apple zoo banana apple cherry` のtop 1/2/10でも総数6、別の頻度入力 `beta beta beta alpha gamma alpha delta` のtop 2でも総数7、表の上の表示位置、既定10・種類数超過・空入力0行を確認する。利用説明へ実行と保存の使用例を追記する。
- [ ] 2.3 同じ入力のtext/json/htmlの語・回数・順序を照合し、html指定でも不正top（0・負・非整数）、不正format、引数個数、読込み/デコード失敗のexit・stderr・空stdout、Unicode抽出・casefold・入力境界を回帰試験する。特殊文字を含む有効なbasenameをCLIで検査し、単語認識を緩めない。text/jsonの構造・空出力は同数時順序以外に変更せず、試験結果で確認する。

- [ ] 3.1 明るい背景のみ・切替なし・1始まり表示行連番を適用し、長い語とbasenameを折返して読める表にする。通常幅と320 CSS pxの実CLI生成HTMLで、空・通常・長文・同数topの表示を試験し、順位1/2、横はみ出しなし、省略なしを確認する。採用したUIと確認条件を説明文書に残す。
- [ ] 3.2 ブラウザ検証手順と必要なローカル補助を用意し、viewport・要素・文字Range行断片・切取り祖先・隣接内容の実測原本および画面画像を保存する。横方向の収まり、切取り祖先内の収まり、隣接内容との非重複、画像の可読性で判定し、要素自身への厳格な縦包含を必須にしないことを試験/手順で確認する。値を補正して合格に見せず、全文を確認できる画像と実測を対応付ける。
