2. 後続PM/最終化が公式チームD.5を読む。full工程の原本・PLAN・SUMMARY・品質文字原本を保存・push・標準カード添付し、その実体を確認した後に指定ファイル限定整備を行う。個別の工程ファイル削除では代用しない。D.5の破壊的コマンドはここで推測しない。
3. 整備後、品質が対象PRのメタデータを既存公式チーム照会経路で読み直し、実際のbase branch（期待v112-a）、base/head完全SHA、PR識別子を文字原本に記録する。移動refや途中headで代替しない。Git objectがなければ既存許可経路で取得し、取得不能なら検証不能で止める。メタデータの再読取りができなければ最終判定しない。
4. BASE/HEAD_SHAをその実PRの完全SHAへ設定し、以下をrootから実行する。ここは将来実在するPRを入力とする後続runbookであり、Builder task検証の前提ではない。各Git出力を省略せず文字原本へ保存し、manual direct readingで合否を付ける。

```sh
git rev-parse --verify "${BASE}^{commit}"
git rev-parse --verify "${HEAD_SHA}^{commit}"
MERGE_BASE=$(git merge-base "$BASE" "$HEAD_SHA")
git --no-pager diff --no-ext-diff --no-textconv --no-relative --name-status "${BASE}...${HEAD_SHA}"
git --no-pager diff --no-ext-diff --no-textconv --no-relative --name-only "${BASE}...${HEAD_SHA}"
git --no-pager show "${MERGE_BASE}:README.md"
git --no-pager show "${HEAD_SHA}:README.md"
git --no-pager diff --no-ext-diff --no-textconv --unified=40 "${BASE}...${HEAD_SHA}" -- README.md
git diff --check "${BASE}...${HEAD_SHA}"
```

5. fails_when（manual direct reading）: 最終全一覧が空、README不在、README以外（工程含む）が1件でもある、指定例不在/重複/値違い、既存本文/末尾の破壊なら該当条件fail。SHA/PR対象違い、出力省略、merge-base未取得なら検証不能。diff表示/diff --checkのexit0ではgreenにしない。2条件を別々に判定し、PR base/headが変われば全項目を再取得する。
6. 品質が新しい対象のVERIFICATION.mdとCLI文字原本を標準添付する。PMはread_fileでその原本を読み受入判断する。BuilderはOpenSpec2.1の品質/PM分を自己承認しない。未実施をpendingとし、probe/prohibitionのflagを人の解決なしに消さない。
